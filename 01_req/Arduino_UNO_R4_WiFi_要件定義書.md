# 1. はじめに
本書は、Arduino_UNO_R4_WiFiのマイコンボード開発手順書作成の要件定義書である。<br>

# 2. 概要
手順書を最後まで進めることで、Arduino UNO R4 WiFiのマイコンボード開発ができるようになることを目的とする。<br>

# 3. 要件
- 構成<br>
章番号と名前はテンプレートのまま変えない。<br>
当てはまらない章は消さずに残し、作らない理由を記載する。<br>

- 改版履歴<br>
版は0.1から始め、コミットする度に0.1上げる。<br>
承認されたら1.0に上げる。<br>
日付は yyyy/mm/dd 形式で記載する。<br>

- 概要 (第0章)<br>
手順書を進める前に何を準備すればよいかわかるように記載する。<br>

- 開発の準備 (第1～3章)<br>
使用するツールが何も入ってないパソコンから始めても、手順書だけで準備が終わるように書く。<br>
インストール途中で表示される画面のスクリーンショットをつける。<br>

- 題材の作成 (第4～5章)<br>
題材の節は<br>
　① 作るもの (ボードの動き)<br>
　② 配線 (図か写真)<br>
　③ プログラム (コメント付き)<br>
　④ ビルドと書き込み<br>
　⑤ 動作確認<br>
の順番で記載する。

- デバッグとまとめ (第6～8章)<br>
トラブルシューティングは環境構築や題材でつまづいたことを記載する。<br>
参考資料は参考にした公式資料やWebページのリンクを箇条書きで記載する。<br>

- 記述ルール (全章で揃える)<br>
    - 見出し<br>
    章は「## 1. 開発環境構築」、節は「### 1.1 ツールのインストール」のように記載する。<br>
    - 手順<br>
    番号付きリストで書き、1つの番号に1つの操作。文末は「〜する。」に揃える。<br>
    - 確認<br>
    手順のあとに「> 確認:〜れば成功」と、成功したかどうかの判断方法を記載する。<br>
    - 注意<br>
    間違えやすい所は「> 注意:〜」と記載する。<br>
    - 画像<br>
    画面操作にはスクリーンショットを付ける。<br>
    images/ に置き、名前は担当番号から始める(例:u1_ext.png)。<br>
    - 図<br>
    処理の流れやタスクの関係は Mermaid で記載する。<br>
    配線は図か写真で、ピン番号を記載する。
    - プログラム<br>
    手順書の中にコードブロックで書き、日本語のコメントを付ける。<br>
    - バージョン<br>
    ツールと SDK のバージョンを記載する。<br>
    - 用語<br>
    同じものは同じことばで記載する。<br>
    英数字は半角で、日本語との間に半角スペースを入れる。<br>
    - つまずいた点<br>
    第7章に必ず記録する。<br>
